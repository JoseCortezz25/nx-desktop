# Visual evidence — issue #8, QA round 1

- **Validation type:** `scoped-visual` (binding)
- **Scope:** the approval chip and the context bar (project picker + environment popover) — **not** the whole screen
- **Viewport:** 1440x900 desktop, `deviceScaleFactor: 1`, capture mode `clip` (element clip inside a 1440x900 viewport)
- **App:** `pnpm dev` → `http://localhost:1420/`, branch `feat/issue-8-approval-environment-project-picker` @ `cec0e3c`
- **Baseline:** generated by `visual-baseline-setup/scripts/create-visual-baseline.ts` from the wireframe HTML in `docs/wireframes/`
- **Diff:** computed with `visual-qa-evaluation`'s own primitives (`pixelmatch` + `pngjs`) over two identically-scoped clips

## Why the current side is a clip, not a viewport

`evaluate-visual-diff.ts` captures the **current** side as a full-viewport screenshot
(it accepts no `--selector`), while `create-visual-baseline.ts` supports `--selector`
(clip). A clip baseline therefore cannot be compared through the wrapper script: the
script resolves the baseline manifest's _render viewport_ (1440x900) and reports
`dimension-mismatch` against the 554x181 clip. The run is kept in
`tooling-approval-popover-eval.report.json` for the record; the comparison itself uses
the same `pixelmatch`/`pngjs` primitives the script is built on, over two clips captured
the same way.

## Capture index — every capture states the accessible name it asserted

The app side was targeted by **role + accessible name** (`getByRole(...)`), and the
`aria-label` was read back and asserted **before** the screenshot was written. A mismatch
throws and aborts the capture. The bare assertion results are in `qa-observations.json`
(`assertions[]`, all `ok: true`).
