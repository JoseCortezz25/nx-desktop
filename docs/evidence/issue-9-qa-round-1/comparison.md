# Visual comparison — issue #9 create-project dialog vs wireframes 04/05/06

Binding validation type: **`visual+functional`**, visual readiness **ready**, baseline viewports **900x700** and **1440x900**.

**Baseline reference:** `docs/wireframes/04-project-picker.html`, `docs/wireframes/05-create-project-empty.html`, `docs/wireframes/06-create-project-folder.html` at commit `37736c5a8849a754a872f31d03d63b22384cdc3b`. These are **low-fidelity grayscale wireframes** that show layout and behaviour, not final visuals or copy (`docs/wireframes/README.md`, "Ground rules for implementation").

**Comparison method:** structural + geometric, not pixel parity. The wireframes and the live app are not pixel-comparable (see `manifest.json` → `nonComparableDimensions`): the wireframes are fixed ~1600px mid-fidelity renders that draw the native title bar (superseded by #42), while the app is a live shell at the requested viewport with no drawn native frame and with real runtime copy. The question answered is the one the issue asks: **does the specified dialog/picker state and shell structure render as drawn, and is the shell behind it intact?**
